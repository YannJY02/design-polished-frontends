# Design Polished Frontends

[English](README.md)

[![skills.sh](https://skills.sh/b/YannJY02/design-polished-frontends)](https://skills.sh/YannJY02/design-polished-frontends)

Design Polished Frontends 是一个面向完整前端交付的 Agent Skill。它帮助编码智能体从产品目标出发，在现有技术栈中完成设计与实现，并在用户真正使用的界面上验证结果。

它适用于网站、Web 应用、数据看板、组件系统、浏览器扩展、移动应用、桌面应用和嵌入式界面。工作不会停在一张好看的截图上。这个 Skill 还会检查响应式布局、真实状态、可访问性、性能、不同输入方式和运行时证据。

## 安装

```bash
npx skills add YannJY02/design-polished-frontends@design-polished-frontends
```

安装到指定 Agent：

```bash
npx skills add YannJY02/design-polished-frontends \
  --skill design-polished-frontends \
  --agent codex
```

在任务中调用：

```text
使用 $design-polished-frontends 重新设计这个产品，完成主要用户流程，并在真实目标界面上验证结果。
```

## 它解决了什么问题

很多前端 Skill 主要给出视觉方向，或者直接生成一轮代码。这个 Skill 负责完整的交付闭环。

### 从产品任务开始，而不是套用风格模板

Agent 会先确认用户、主要任务、信任需求、目标平台、自适应尺寸、必要状态和验收条件。面对已有产品时，它会把现状分为保留、改进和替换，避免重做一切，也避免为了视觉变化破坏已有优势。

### 按真实需要选择资源

Skill 可以使用项目现有组件、平台原生控件、专业设计 Skill、浏览器工具、模拟器、权威资料和经过筛选的素材。只有真正读取、调用、打开、运行或检查过，并且影响了设计或验证结果的资源，才算被使用。

每条资源路线都会留下简洁记录：

```text
Need | Kind | Executed capability/source | Observed evidence | Decision | Applied delta | Verification
```

因此，整个设计过程可以检查和追溯。只列出工具名称不算证据。

### 根据实际平台改变做法

Web 项目优先使用语义化 HTML、CSS、浏览器诊断和项目已有组件。Apple 平台优先采用 SwiftUI 或 AppKit 的原生模式。浏览器扩展需要在实际宿主中运行。桌面和跨平台应用则应在真实运行时中验证，只要当前环境能够提供该运行时。

### 检查状态、交互与可访问性

目标界面验证会覆盖代表性尺寸和主要用户流程，也会检查导航、表单、菜单、对话框、焦点顺序、键盘与指针操作、必要时的触摸输入、文字缩放、减少动态效果、加载、失败和恢复状态。

综合评分只是摘要。即使总分看起来正常，高影响问题仍然需要单独检查、修复并重新验证。

### 对验证结果保持诚实

如果真实应用、模拟器、设备或宿主无法运行，Skill 会使用当前最接近的可运行环境，并明确指出缺口。浏览器预览不能证明原生应用已经通过验证。构建成功也不能证明交互流程正确。

## 交付流程

| 阶段 | 结果 |
| --- | --- |
| 定义 | 简洁的产品说明、目标界面、验收矩阵和停止条件 |
| 选路 | 只按需要选择并验证设计、实现、素材、可访问性、性能和 QA 路线 |
| 构建 | 在当前技术栈中完成统一的实现，包括真实状态和自适应行为 |
| 验证 | 在真实目标界面或明确标注的替代环境中运行主要用户流程 |
| 交付 | 给出检查结果、路线记录、仓库状态和准确的交付结论 |

## 适合这些任务

- 根据产品说明或已有后端构建新的前端界面。
- 改造现有网站或应用，同时保留有效的结构和组件。
- 把数据看板、浏览器扩展、移动端、桌面端或嵌入式界面推进到可交付状态。
- 创建或修复组件系统，并验证典型组合、变体、状态和可访问性行为。
- 把视觉上不错的原型变成经过响应式、可访问性、性能和运行时检查的真实产品界面。

如果任务只是独立代码审查、单一故障诊断或单纯部署，应使用范围更窄的 Skill。

## 支持的前端目标

- 网站、落地页、PWA、Web 应用和数据看板
- 设计系统和组件库
- 浏览器扩展和 WebView
- iOS 与 macOS 前端
- 其他移动端、桌面端、跨平台和嵌入式界面，前提是当前环境能够提供相应运行时或模拟器

## 常见问题

### Design Polished Frontends 是什么？

它是一个可复用的 Agent Skill，用来协调前端产品定义、设计决策、代码实现、真实界面 QA、可访问性、性能检查和交付证据。

### 它和普通的前端设计提示词有什么不同？

普通提示词通常只改善一轮输出。这个 Skill 定义了一套可以重复执行的交付约定。它会检查当前项目，按具体需要选择资源，完成可运行的主要流程，并在宣布交付前验证真实行为。

### 它会强制使用某个框架或设计系统吗？

不会。它首先复用当前技术栈，然后考虑平台原生能力、当前可用的 Skill、已经安装的依赖，以及能够补上已确认缺口的最小新增资源。

### 它会自动部署吗？

只有任务已经要求或授权部署时才会进行。否则，它会停在已经验证的可部署产物。

### 每个环境都能执行所有路线吗？

不能。不同 Agent 和设备提供的浏览器、模拟器、设计与部署能力并不相同。这个 Skill 会记录实际运行过的路线，并明确说明尚未验证的目标。
